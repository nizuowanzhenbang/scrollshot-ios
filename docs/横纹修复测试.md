# 横纹修复候选：0.3.0 build 5

本次只修改原尺寸拼接校准，不改变采集频率。原始草稿和帧文件保留。

## 已复现的问题

原尺寸校准仍按高度跳行采样，2400 行图像每 13 行才比较一次，可能遗漏细小文字。搜索窗口固定为估计位移前后 12 像素，无法纠正小图估算的累积误差。在重复纹理的合成回归用例中，实际 220 像素的位移被可靠性检查接受为 180 像素，会在接缝漏掉 40 行。

修复后，提供估计位移的校准阶段逐行比较；搜索半径为有效画面高度的 1/16，至少 12 像素。不确定的匹配仍然拒绝。录屏实时分析沿用原有轻量采样。该复现证明算法存在缺陷，但尚不能证明用户提供的横纹全部来自此原因。

## 真机测试

1. 安装 build 5 测试包，保留原草稿；不要先删除旧版或清理数据。IPA 仍需使用有效证书重新签名，标准版须保留录屏扩展和共享组。
2. 先对之前有横纹的草稿点击重新生成，再保存 PNG。重新生成会清除该结果的裁剪/马赛克编辑，请先保存需要保留的旧结果。
3. 在同一个聊天页面录一段 5–10 屏的滚动：普通速度一段、较慢速度一段。另测短暂停顿和少量回滚。
4. 放大查看文字接缝、重复气泡与长段文字：是否还有横线、重复行、缺行或突然分段。对比应用内预览与保存到相册的 PNG。
5. 反馈使用标准版还是导入版、手机/iOS 版本、重新生成耗时，以及接缝局部截图。仍有横纹时，保留对应原始录屏或草稿用于进一步定位。

当前 Linux 本地验证只涵盖实际 Swift 匹配器和 Python 包校验测试，Apple 图像处理及真机采集需 macOS/手机验证。`bash scripts/test-matching.sh` 可在有 Swift 的 Linux/macOS 上运行匹配测试；Mac 上运行 `swift test` 覆盖完整核心测试。

## 节省构建额度

测试分支 `fix/scroll-seams` 不在 push 自动构建分支列表内。手动运行现有 `build.yml`，选择该分支并开启 `preview_only`，只运行一个 Mac 作业：核心测试、两个 IPA 打包、包结构校验；跳过重复核心作业和模拟器 UI 测试。产物保留 3 天，不创建 Release，也不合并默认分支。正式发布前仍需完整模拟器检查和真机验收。
