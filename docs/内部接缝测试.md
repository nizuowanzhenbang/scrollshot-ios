# 标准版 build 7：内部接缝修复

针对用户截图中反复穿过文字、时间和表情的横向暗带，先在本地复现了一种与之相符的机制：真实固定栏比每帧裁剪范围高一点时，即使帧间位移完全正确，旧计划也会把上一帧底边残余栏反复拼进长图。没有原始采集帧，尚不能证明用户图片中的每一条暗带都来自这一机制。

## 改动

- 从重叠区内部接图，替换上一帧的重叠尾部；默认接缝在重叠区中部，不再只追加新帧末尾。
- 原尺寸校准后，比较两帧对应区域的差异和纹理，在远离两帧边缘的区域内优先选择相对稳定、平坦的窄带，降低穿过文字和动态表情的概率。
- 仅对最终保留的覆盖帧进行接缝比较；反向/重复采集不替换参考帧，接缝不能倒退到已被其他帧接管的区域。原尺寸宽度、场景变化或覆盖断开时重置参考。
- 接缝位置随校准后的预览帧保存为可选字段，旧草稿仍可读取；不修改原始采集帧。预览和 PNG 导出共用拼接计划。
- 仍按真实覆盖范围计算总高度，不通过删掉横带来遮盖内容；反向、重复帧、场景切换和超长分图规则保留。

PixelRect/PageEdit 的原有定义仅移到 `Core/ImageGeometry.swift`，使匹配器、接缝和计划能够在 Linux 上运行真正的 Swift 测试；没有更改图像编辑的数据格式。

## 本地复现与检查

固定栏测试：每帧高 100 行，实际上下固定栏各 12 行，裁剪各 10 行，位移为 0、30、60 行。旧计划在逻辑文档第 88、89、118、119 行引入固定栏；新计划内部保留的逻辑行必须完整等于 12..<148，不能缺行或重复。最外侧两行仍属于需要用户裁掉的真实固定栏，不假造缺失内容。

其他测试覆盖安静带与动画的选择、正反方向一致性、旧 JSON、反向和重复运动、裁剪/分图边界。`RenderTests` 另检查从帧校准到真实 PNG 输出的内部行像素。`bash scripts/test-matching.sh` 在本地运行可移植部分；完整 `swift test` 在 Mac 构建作业中运行。

## 真机验收

1. 安装 build 7 标准版，保留旧草稿，不先卸载应用。
2. 先保存需要留存的旧结果，再对刚才失败的草稿点“重新生成”。此操作会清除该结果的裁剪/马赛克编辑，原始帧保留。仅安装新版不会改变之前生成的 PNG。
3. 对比之前每条横带处的文字、时间与表情；保存或复制后再放大确认，检查是否有缺行或重复行。
4. 再测试同一聊天页面的普通滚动、短暂停顿和少量回滚。若只有最顶部/最底部剩下界面边缘，可调整对应裁剪后重新生成。
5. 若内部横带仍存在，保留该草稿和对应原始录屏；接下来需检查原始帧是否已有损伤或实际接缝是否来自动态内容。

仅构建标准版，不创建正式 Release，等待用户测试再决定是否合并。
